# Independent architecture seam review

**Initial verdict: ACCEPT WITH BOUNDARIES. Resolution review: ACCEPT / RATIFIED.** The design preserves the existing Go system, maps all PRD AC-01–15, and keeps product G0/G3/G4/G5 unaccepted. The five previously identified seams are now closed in AD-3, AD-7, AD-8 and AD-9. No remaining integration blocker was found in those additions.

| Severity | Seam / divergent implementations | Concrete closure |
|---|---|---|
| High | **AC-08/09/04/06 event reducer output and ownership.** AD-7 defines rejection conditions but no canonical verifier function/CLI, input framing, result schema, or exact output artifact. One writer could patch existing functional TestMain to fail on skip; another could build a separate JSON-event reducer. Both meet the prose while emitting incompatible evidence, and AC-09 negative controls may test different branches. | At L0 freeze the existing assertion owner and exact entrypoint/file(s); specify one versioned fixture format and exact invocation/output fields for mandatory identities, observed events, package terminal event, exit code, status (PASS, FAIL, BLOCKED), and reason. Use the same reducer contract for AC-04/06/08/09 or state explicitly why not. Preserve Go's actual test JSON and process exit separately. |
| High | **Runtime canary request/effect evidence (AC-10).** AD-4/5/6 name the required evidence, but “authorized request/audit/effect evidence” and bounded cancellation/deadline are not bound to an existing interface or receipt field names. A runtime observer can claim zero GitHub writes from API response/dry_run; another can require an audit log, so G3 results differ. | Before R1, bind the observed interface/version and name the exact available request, terminal-readback, effect/audit and deadline fields. If no effect inventory exists, declare AC-10 BLOCKED for zero-write predicate; do not infer from dry-run. Receipt must distinguish request intent from observed effects and include interval/generation. |
| Medium | **Receipt identity and hashing granularity.** AD-9 requires raw artifact paths/hashes and exact labels but does not define encoding/canonicalization for multi-file evidence or whether each output stream, request, result and snapshot is a separate artifact. A reviewer can hash normalized JSON while another hashes raw bytes and both cite SHA-256. | Reuse a concrete receipt template if present; otherwise freeze one manifest convention at P0: one row per raw artifact, repository-relative path or environment-labeled URI, byte count, media type, SHA-256 over stored bytes, and an explicit sanitized/redacted marker. Never hash transformed evidence as though it were raw. |
| Medium | **AC-11 witness/adjudication mapping.** Oracle contents are strong, but the join key from each emitted finding to expected cause, pinned file/line, head/mitigation witness and negative control is prose-only. QA could accept a finding by title/location while another requires explicit evidence linkage; “every critical/important claim” also lacks a deterministic per-finding record shape. | Freeze a reviewer-owned per-finding adjudication table before R2: finding identifier/hash; severity; cited pinned source range; expected-cause match; head witness; mitigation witness; negative-control result; evidence decision; reviewer verdict/reason. Define absent witness as BLOCKED_SELECTION/NOT_APPLICABLE only with recorded rationale, never implicit pass. |
| Medium | **AC-03 tag predicate ambiguity.** AD-3 says missing tags narrow the claim while AC-03 requires child tags checked “when exposed.” Independent parsers may pass exact names/callback and silently omit tags even when discovery returns an empty/malformed tag field. | Define tag status per reasoner as observed exact, absent from API, malformed, or mismatch; only the first two are non-failing, with absent from API narrowing the claim. Empty/malformed exposed tags must not be treated as unavailable. |

**Resolution:** AD-3 defines `EXACT`, `API_FIELD_ABSENT`, `MALFORMED`, and `MISMATCH`, including empty/null handling. AD-7 freezes one L0/L1 owner and `go-test-events/v1` input/output receipt contract across AC-04/06/08/09, retaining raw stdout/stderr and process status. AD-8 provides a per-finding result-hash/index adjudication join and separate negative-control rows. AD-9 defines `pr-af-evidence/v1` byte-level artifact manifest plus `pr-af-runtime/v1` observed-interface field mapping; absent complete effect inventory or deadline/terminal reconciliation hard-blocks AC-10. These closures address each divergence described above while keeping implementation location deferred to L0 as the PRD requires.

**PLAN/PRD alignment:** The architecture correctly defers all implementation to P0/L0 and reiterates PLAN authority. The PRD says planning status is not PLAN_ACCEPTED, and the architecture correctly says this document does not grant it. Therefore initial R0/L0/S0 are a candidate frontier only; none is released until canonical PLAN admission is recorded. Runtime tasks remain separately gated on CURRENT identity and execution authority.
